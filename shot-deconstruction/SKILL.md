# 镜头解构

把非结构化参考视频转为可复用的“镜头—纯文字提示词”资产。职责是观察、拆镜和重构生成条件，不负责创意策划、脚本撰写或最终视频生成。

面向新用户的完整流程、输入与输出说明见 [`使用说明.html`](使用说明.html)。

## 宿主 Agent 兼容约定

1. 本 Skill 不依赖固定产品名或工具名。把“执行命令、读取元数据、查看图片、写入文件”等能力映射到宿主 Agent 提供的等价工具。
2. 所有相对路径均以当前 Skill 目录为基准解析；执行到对应阶段时再读取相关 `references/` 文件。
3. 宿主不支持自动 Skill 发现时，将本 `SKILL.md` 作为项目或系统指令加载，并同时提供 `references/`。
4. 宿主无法执行本地命令或查看视频帧时，不宣称完成视频解构；请求用户提供关键帧与元数据，或明确报告缺失能力后停止。
5. 网络访问、软件安装和文件覆盖均遵循宿主平台的权限机制，不因本 Skill 被调用而获得额外授权。

## 版本与整包更新

当前 Skill 版本读取 `SKILL.md` frontmatter 中的 `metadata.version`，本版为 `1.2.1`。输出文件中的 `schema_version` 是数据结构版本，与 Skill 版本分别管理。

当用户指定一个新版 Skill 文件夹并要求更新已安装版本时：

1. 分别读取已安装文件夹和新版文件夹 `SKILL.md` 中的 `metadata.version`；点分数字按数值逐段比较，例如 `1.10` 高于 `1.2`。
2. 新版缺少版本号时停止更新并报告；已安装版本缺少版本号时视为 `0`。
3. 只有新版版本号高于已安装版本时才更新。确认新版至少包含 `SKILL.md` 及其引用的必要文件后，用新版文件夹的全部内容完整替换已安装文件夹，不进行逐文件比较、合并或保留旧文件。
4. 新版版本号等于或低于已安装版本时不更新，并报告当前版本与指定版本。
5. 替换完成后重新读取已安装 `SKILL.md`，确认版本号已变为新版版本，并报告更新结果。

## 核心原则

- 分开保存观察事实、镜头判断与提示词重构；不宣称找回原始提示词。
- 每个镜头只生成一种可独立使用的中文纯文字复刻提示词。
- 提示词使用稳定的信息逻辑，但按镜头动态复杂度调节篇幅与时间表达，不把所有镜头机械套入同一长模板。
- 先粗后细，按动态复杂度增加取样，不增加独立运动时间轴，也不对所有视频固定高密度采样。
- 用视频 SHA-256 作为复用键；已有同哈希资产时优先报告并复用，除非用户要求重新分析。
- 不把可识别真人、品牌、受保护角色、平台叠层或明显生成瑕疵作为应复刻的核心特征。

## 分层架构与加载规则

| 阶段 | 文件 | 产出 |
| --- | --- | --- |
| 视频预检完成，尚未拆镜 | `references/video-inspection.md` | `inspection_record`（观察事实） |
| 将候选边界判定为最终镜头 | `references/shot-analysis.md` | `shot_analysis`（镜头判断） |
| 为最终镜头生成纯文字提示词 | `references/prompt-reconstruction.md` | `text_to_video_prompt_zh` |

按 `RECEIVED → INSPECTING → SHOT_ANALYSIS → RECONSTRUCTING → DELIVERED` 执行。

## 运行时依赖

读取输入前检查 `ffmpeg` 和 `ffprobe`。两个命令可用时直接继续，不擅自替换或升级。缺失时先报告影响并征得用户授权，再从系统受信任软件源或 FFmpeg 官方下载页列出的预编译渠道补齐；宿主无安装权限时让用户处理。安装后重新验证两个命令，仍不可用则报告原因并停止。

## 1. 接收与预检

1. 确认视频可读取且时长大于零。
2. 只把文件名、SHA-256、时长、分辨率和帧率作为强制交付元数据。编码、容器、文件大小、帧数和音轨细节仅在诊断问题时读取或报告。
3. 在用户指定资产库或当前工作区查找同哈希 `manifest.json`；发现可用资产时先报告路径和创建时间。
4. 预检只读取元数据并准备取样，不生成提示词或最终镜头结论。

### 分析代理

当原视频像素数超过 `2,073,600`（1080p）或最长边超过 `1,920 px` 时，创建最长边不超过 `1,280 px`、保持比例且宽高为偶数的分析代理；仅缩小，不放大。普通关键帧和连续帧优先从代理抽取，只有小文字、细微道具、纹理或边界证据无法确认时才从原视频补取少量局部帧。

## 2. 观察、拆镜与纯文字提示词重构

1. 读取 `references/video-inspection.md`，形成带时间锚点的观察记录。
2. 读取 `references/shot-analysis.md`，把候选区间判定为最终镜头。首镜头从 `0.00` 开始，末镜头结束于实际时长，相邻镜头不得留空或重叠。
3. 读取 `references/prompt-reconstruction.md`，从已验证观察生成 `text_to_video_prompt_zh`。提示词不依赖参考素材，按“主体与核心动作 → 场景空间 → 动作时序 → 摄影机 → 光影风格 → 可选声音 → 稳定约束”的逻辑组织，并按镜头复杂度压缩为自然语言导演指令。
4. 不增加独立运动时间轴。用 `start_state`、`action_chain`、`end_state` 和 `camera_motion` 表达镜头内部变化；不确定项写入 `uncertainties`。

## 可选音频分析

默认不提取、不转写，也不分析音乐或旁白。只有用户明确要求声音、音乐、旁白或声画关系分析时，才在视频观察阶段执行相应分析，并在 JSON、Markdown 和 HTML 中增加 `audio_observation`/“声音观察”内容；有音频观察证据时，可将与当前镜头相关的声音时序编译进纯文字提示词。用户未要求时不生成占位式音频结论，不在提示词中臆造声音，也不让音频能力影响视觉解构的完成。

## 交付与资产沉淀

在 `video-deconstruction-assets/<sha256前12位>/` 创建：

```text
video-deconstruction-assets/
  <sha256-12>/
    analysis.html       # 最重要的用户交付：离线图文对照报告
    analysis.md         # 便于检索、复制和人工审阅
    analysis.json       # 下游 Agent 的机器读取入口
    manifest.json       # 复用索引
```

### `analysis.json` 核心契约

以下核心字段必须存在；`audio_observation` 仅在用户要求音频分析时增加。

```json

  "schema_version": "1.5",
  "asset_id": "sha256前12位",
  "source_video": {
    "filename": "input.mp4",
    "sha256": "完整sha256",
    "duration_seconds": 0.0,
    "resolution": "1920x1080",
    "fps": 24.0
  },
  "global_observation": {
    "summary": "",
    "visual_style": [],
    "editing_rhythm": "unknown"
  },
  "shots": [{
    "shot_id": "S01",
    "start_seconds": 0.0,
    "end_seconds": 3.25,
    "time_range": "00.00秒-03.25秒",
    "observation": {
      "subject": "",
      "environment": "",
      "start_state": "",
      "action_chain": [],
      "end_state": "",
      "camera_motion": "",
      "composition": "",
      "lighting_color_style": ""
    },
    "text_to_video_prompt_zh": "可独立使用的完整中文提示词",
    "continuity_notes": "",
    "uncertainties": [],
    "safety_rights_notes": []

```

`analysis.md` 固定包含“视频信息”“全局视觉观察”“解构方法摘要”“镜头—提示词映射”“连续性、不确定项与权利提示”。用户要求音频分析时再增加“声音观察”。

`manifest.json` 至少记录 schema/技能版本、创建时间、输入 SHA-256，以及三个分析文件的路径。

### `analysis.html` 图文对照报告

HTML 是最重要的用户交付，必须离线可打开且不依赖外部资源。

1. 页首显示文件名、总时长、分辨率、镜头数、生成时间和全局视觉摘要；用户要求音频分析时再显示声音观察。
2. 每个镜头对应一张卡片。桌面端左侧显示 `shot_id`、`time_range` 和镜头截图，右侧依次显示观察摘要、纯文字复刻提示词、连续性和不确定项；窄屏改为上下布局。
3. 截图默认使用镜头中点附近的有效帧，最长边不超过 `960 px`，保持比例且不放大。显示实际截图时间；无法抽取时明确说明原因，不伪造画面。
4. 截图以 JPEG `data:` URL 内嵌。报告不引用外部 URL、脚本或第三方资源；所有用户可见文本做 HTML 转义，图片 `alt` 包含镜头编号和截图时间。

## 临时文件

关键帧、连续帧、分析代理和其他中间文件只写入本次任务专用目录，例如 `work/video-deconstruction/<sha256前12位>/`，不得混入交付资产目录。交付后若该目录包含文件，告知用户目录位置并询问是否清理；没有临时文件时无需询问。用户确认前不删除；确认后只删除本次专用临时目录，保留全部交付资产。

## 质量门槛

- 镜头按时间排序，覆盖完整视频且无空隙或重叠；
- 观察与提示词一致，不把推测伪装成事实；
- 每个镜头都具有可脱离源视频独立使用的纯文字复刻提示词；
- 提示词逻辑顺序稳定，但篇幅与时间连接词符合镜头动态复杂度；
- 标准动作镜头明确开始状态、动作过程和结束状态，复杂连续动作按触发、展开、完成表达；
- 稳定性要求优先使用少量正向约束，不堆叠通用负面词；
- 只有存在经验证的音频观察时，提示词才包含声音内容；
- `analysis.json` 可解析，时间文本与数值时间一致；
- `analysis.html` 包含每个镜头的截图或明确不可用原因，并清晰展示纯文字复刻提示词；
- `analysis.md`、`analysis.json`、`analysis.html` 和 `manifest.json` 均已生成；
- 未经用户要求，不执行音乐或旁白分析。

下游 Agent 读取 `analysis.json`；用户优先查看 `analysis.html`。复刻单一画面时使用对应镜头的提示词，不把整条视频合成一条提示词。
