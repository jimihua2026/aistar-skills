# 返修决策

先定位最早出现问题的环节；每轮优先修正一个主要变量，并保留修正前后的输入和结果。

| 现象 | 优先检查 | 修复动作 |
|---|---|---|
| 数量错误或多出主体 | 目标关键帧是否已经错误 | 局部修正图像，逐件计数后再生成 |
| 器物滑动、位置交换 | 首尾帧的坐标、尺度、视角是否冲突 | 修正尾帧或取成功视频实际尾帧续接；不只增加“保持一致” |
| 看似两图叠化 | 中间动作状态是否存在 | 补充物理变化过程，必要时拆为可验证的动作阶段 |
| 形变破坏建筑结构 | 固定外框与可变表皮是否分清 | 固定背景，生成局部运动，必要时分层合成 |
| 花朵或道具突然出现 | 起止图之间是否缺少发生机制 | 写清来源、触发、生长和完成；复杂动作拆段 |
| 角色身份漂移 | 各图猫/人/产品是否已不一致 | 复用同一角色参考修图，再继续视频 |
| 实体入画后构图不同 | 目标绘画是否重排物体 | 使用同构图画芯，风格变换不改变轮廓与遮挡 |
| 后拉露框换成另一幅画 | 模型重新绘制了画芯 | 固定实际已通过的画芯，后期做缩放与画框合成 |
| 分段均成功但接缝跳动 | 前段实际尾帧与后段实际首帧 | 比较接缝附近连续帧；再决定续接、剪辑或局部重做 |
| 画面正确但动作先后重叠 | 严格时序是否为验收硬条件 | 硬条件则返修；用户接受则记为有偏差通过，不写全部指令满足 |
| 平台提示敏感内容 | 完整报错及触发输入是否明确 | 对正常任务简化为中性画面描述，分别排查图文；不猜测禁词清单 |
| 提交超时或状态不明 | 是否已产生平台任务 | 先查已有任务，不直接重新提交重复计费 |

像素差只是接缝辅助证据；数值低不保证观感无缝，也不能作为跨项目统一阈值。

## 测试何时停止

代表样例覆盖本项目关键机制、用户已认可且无阻断问题时，结束试验并整理交付。不要把每个镜头都验证一遍作为交付制作指令Skill的先决条件。

有差异时分清核心目标、严格约束和可接受偏差。未验证的声音、整片节奏和批量稳定性继续标为未验证。测试片长不能直接替代原片时长；正式剪辑根据实际节奏处理。


全片返修前用版本、任务编号、时间和画面锁定目标，具体流程见[全片返修与收尾](film-closeout.md)。
