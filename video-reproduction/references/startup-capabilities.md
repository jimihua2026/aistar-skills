# 启动能力与协作分工

中文名称：视频复刻。目标是确定本次工作谁来执行、在哪里执行、缺什么输入；不是让用户填写一张冗长问卷，也不是探测或安装所有可能的工具。

## 先明确范围，再检查能力

继承已有参考片、替换目标和交付范围。范围采用instructions（制作包）、images（实际替换图）、clips（视频片段）或film（完整影片）；这表示目标，不表示已完成。声音只在要求声音分析、声音复刻或有声成片时加入检查。

优先只读检查已有工具清单、素材是否可读、已有文件及用户确认参数。工具存在只能证明接口被列出；实际可用要有读操作或成功结果佐证。不会为测试能力提交付费生成、上传私有素材或申请无关权限。账户、授权和费用边界与技术能力分别记录。

## 能力检查表

| capability id | 要检查什么 | 何时需要 | 无此能力的协作方式 |
|---|---|---|---|
| file_access | 能否读取参考材料、保存结果并延续项目记录 | 所有范围 | 用户提供可读内容并保存返回的任务文件；未实际保存时标为人工保管 |
| frame_extraction | 能否解码视频、获取时间和提取帧 | 原始输入是视频且需拆解 | 用户或工具提供带时间的截图/连续帧；记录覆盖范围，不宣称已分析未见片段 |
| visual_analysis | 能否实际查看图片/视频帧 | 自动原片观察、关键帧和生成画面验收 | 人工提供观察事实并承担视觉验收；agent仅做文字设计与流程管理 |
| image_generation | 能否制作/编辑目标参考图 | images及需要参考图的clips/film | 外部平台、设计师或已有适用图片；指令包本身无需此能力 |
| video_generation | 能否提交视频生成并取得结果 | clips、film | 用户网页操作或外部服务；记录实际支持的参考模式，不绑定特定品牌 |
| result_return | 外部结果能否按任务编号回传并被读取 | 有外部制作或生成环节 | 指定文件名、目录、版本与接收人；未回传不进入依赖该结果的步骤 |
| video_editing | 能否按取段/速度/顺序剪辑、替换并导出 | film | 剪辑师执行剪辑清单；仅输出清单不能标为已成片 |
| audio_review | 能否实际听辨音乐、音效与声画同步 | 含声音分析或声音验收 | 人工试听并记录结论；波形、转录或文件名不能代替听感 |
| audio_production | 能否取得合适音源并独立剪辑、混音 | 需要新配乐/音效的有声film | 外部声音工具、已有授权音源或声音人员；无需固定为AI生成 |

visual_analysis和image_generation是独立能力，不能用其中一项推断另一项。frame_extraction能导出图片也不代表agent能理解像素。无生图能力不是整个流程的阻断项。

## 状态与证据

每项按needed标记当前范围是否需要。status为verified、unverified、unavailable或not_needed；executor为agent、external_tool、human或unassigned。evidence用简短事实，如“已打开源片第0/2/4秒截图”或“用户确认将由设计师制作”；不要记录密钥、令牌或浏览器会话。

verified表示所选执行路径有依据，不等于产物质量通过。用户确认愿意手动生成，只能证明分工确定；具体生成参数仍按实际平台界面或结果确认。未知项保持unverified，不自动写为不可用或可用。

对外生成另记provider_or_method、authorization（confirmed/pending/not_needed）及spend_limit（未知为null）。不将“技术上能调用”当作“用户已同意付费”，也不重新索要已有明确授权。

## 输出一张简短启动结论

检查完成后给用户：本次交付范围；agent承担的环节；外部工具/成员承担的环节；当前下一步及其阻断缺口。建议用3—5行或一张小表，不把内部字段全部交给用户填写。

所选路线可以是agent_tools（必要环节有可用工具）、assisted（成员或外部工具参与）、instructions_only（仅交付制作包）。没有路由脚本自动接入服务；由agent按已检查证据选择并记录。

缺口只阻断依赖它的阶段。没有图片生成时先完成拆解和外部制图单；无回传图时不假定输入已就绪；不能观察源视频且没有人工观察记录时，不写确定的原片事实。用户说直接开始时不再问可推断的选项，但也不能编造缺失能力。

## 无生图agent的执行流程

1. 观察参考图，建立共享主体、道具和风格规则。
2. 每张图给出source_task_id、输入图实际路径、修改说明、保留项、目标状态、输出文件名和验收条件。没有实际图时状态为planned，不能写ready。
3. 成员在其工具中制作，或由设计师编辑；将结果按任务编号与版本回传。
4. 能看图的agent检查构图、数量、身份与遮挡；不能看图则交给指定成员检查，记录reviewer和method。
5. 通过后再把真实图片路径放入视频任务卡，推进生成。需要返修只更新受影响状态图，并同步引用。

只支持文本的agent可以管理该协作，但不能独立完成参考视频分析和视觉验收。改用纯文字生成视频会减少参考图约束，属于策略变化，不能默认为同等复刻质量。

## 记录与恢复

project.json的capability_check为可选扩展，旧项目无需补齐所有字段才能继续。包含scope、route、status、capabilities、handoffs、unresolved。capabilities每项包含id、needed、status、executor、evidence；可以附provider_or_method、authorization和spend_limit。

handoffs每项说明task_id、output_name、executor、acceptance_owner与status（planned/returned/accepted）。外部执行者获得必要输入与明确输出，不依赖某个agent特有的沙盒路径。新机器恢复时重核路径和服务会话，保留先前用户认可和历史证据。

此表是1.0.0版采用的协作规范，尚未在第二种agent上跑过完整生成项目；结构检查通过不等于跨agent实测通过。
