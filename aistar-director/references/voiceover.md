# Voiceover Writing Protocol

## 文件定位

本文件定义介绍类视频如何从已确认需求和可靠资料中形成可配音、可剪辑、可核验的旁白文字。

核心原则：

> 先确认事实，再组织信息；先匹配画面，再写旁白；先核算时长，再追求文采。

## 1. 触发条件

当视频承担以下任一任务时，默认启用旁白规划：

- 介绍企业、园区、产品、平台、服务、项目或政策背景
- 解释功能、流程、优势、成果或应用场景
- 需要观众在观看过程中获得连续信息

纯氛围片、无信息表达的视觉片，可标记为“无需旁白”，但仍需说明判断依据。

## 2. 资料检索与事实核验

当用户未提供足够的介绍内容时，先判断是否需要外部检索。

资料优先级：

```text
客户正式资料 / 官方网站 / 官方公告 / 官方报告
>
权威行业资料 / 权威媒体
>
一般公开资料
>
AI 推导或常识
```

检索规则：

1. 明确检索对象、时间范围和需要证明的事实。
2. 对企业名称、产品名称、项目数据、政策、时间、地点、排名、客户案例等逐项记录来源。
3. 不把搜索摘要、营销表述或未经核验的第三方内容直接写成事实。
4. 资料相互冲突时，列出冲突、来源和影响，要求用户确认；不得自行挑选。
5. 需要实时或具体事实时，保留来源名称、链接、发布日期或检索日期。
6. 无法确认的内容标为“待确认”或“AI 建议”，不得进入事实锁定。

建议建立：

```yaml
research_item:
  claim:
  value:
  source:
  source_type: client_official | official_public | authoritative_third_party | general_public
  published_at:
  retrieved_at:
  verification: verified | pending | conflicting
  allowed_in_voiceover: true | false
```

## 3. 旁白信息层级

每段旁白只承担一个主要信息任务，并根据画面时长控制信息密度：

```text
段落定位 → 背景问题 → 核心方案 → 工作方式 → 真实价值 → 证据成果 → 行动或收束
```

避免把所有资料堆进旁白。优先保留：

- 观众必须理解的核心信息
- 能被当前画面证明或解释的信息
- 能推动下一段叙事的信息

精确数字、政策原文、产品参数、长名称和复杂清单，旁白只保留必要表达；完整内容可由字幕、图表或后期信息卡承载。

## 4. 旁白写作规则

旁白必须：

- 使用自然口语化、可朗读的句子
- 每句表达一个清晰意思
- 与画面形成互补，不逐字描述画面
- 避免空泛的“赋能、引领、打造、全面助力”连续堆叠
- 对数据、时间、地点、政策和成果使用已核验表述
- 对推测、愿景和创意表达使用明确的未来或建议语气
- 保持整片的人称、语气、术语和品牌用语一致

介绍类视频默认优先采用：

```text
事实说明 + 场景解释 + 价值总结
```

而不是：

```text
口号堆叠 + 形容词堆叠 + 无来源数据
```

## 5. 分段交付字段

每个需要旁白的段落和 Beat 至少记录：

```yaml
voiceover:
  required: true
  text:
  information_role:
  source_claims: []
  source_annotations: []
  versions:
    formal:                # 正式旁白
    review:                # 领导/客户审阅版
    voice_recording:       # 配音版，可含停顿和语气标记
    subtitle:              # 字幕版，按屏幕阅读拆句
  information_density: low | medium | high
  tone:
  estimated_duration:
  reading_speed:
  pause_points: []
  visual_relation: complement | explain | reinforce | contrast
  subtitle_notes:
  verification_status: verified | pending | needs_user_confirmation
```

## 6. 时长核算

旁白时长不能凭字数粗略填充，必须按朗读速度估算并在试读后复核。

默认内部估算：

```text
中文旁白：约 每秒 3.0～4.0 个汉字
庄重、强调、留停顿：约每秒 2.5～3.2 个汉字
快速信息说明：约每秒 4.0～4.5 个汉字
```

计算时额外考虑：

- 数字、英文、专有名词的朗读耗时
- 标点停顿
- 画面留白和信息卡停留
- 段落之间的呼吸间隔
- 音乐起落和转场

旁白时长超过可用画面时长时，按顺序处理：

1. 删除背景性和重复性信息。
2. 将完整数字或清单转为后期字幕/图表。
3. 拆分段落或延长生成单元。
4. 仍无法容纳时，提示用户确认取舍。

## 7. 旁白与画面接口

Storyboard 中必须明确：

```text
旁白开始点
旁白对应画面
关键词出现时的视觉重点
旁白结束点
声音先行 / 画面先行 / 同步进入
```

Prompt 中不重复整段旁白，只在需要原生人声时写入当前镜头的短句；长旁白默认单独录音或配音，并在交付中标注音画接口。

## 8. 质量门

提交用户确认前检查：

```text
□ 每个介绍段落是否明确是否需要旁白
□ 旁白中的事实是否有来源或明确标记
□ 是否存在未经核验的数据、政策、排名或案例
□ 每段是否只有一个主要信息任务
□ 旁白是否与画面互补而非机械复述
□ 旁白时长是否小于可用画面时长
□ 是否标出停顿、关键词和画面对应关系
□ 术语、人称和语气是否统一
□ 无法确认的事实是否已列入待确认
```

旁白质量门未通过时，不得把未经核验的文字交付为正式旁白；可以交付“待核验草案”。
