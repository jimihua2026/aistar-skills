# `references/production-strategy.md`

# Production Strategy Protocol

本文档定义 `aistar-director` 如何为每个镜头和整个项目规划制作方式：
AI 生成、客户素材、实拍、正版素材库、后期制作之间如何分工。

流程位置：

```text
Storyboard
↓
Production Strategy   ← 本文件（与 Storyboard 阶段同步形成）
↓
Seedance Prompt
```

本文件回答的问题：

> **这个镜头应该用 AI、客户素材、实拍还是后期完成？怎样的组合效果、成本、时间综合最优？**

本文件是"制作经济学"层的核心：目标不是提高 AI 使用比例，而是用最低的制作成本，稳定交付客户认可的成片。

---

# 1. 核心立场

视频制作的最终目标是：

> **交付最好、最省时间、最省成本的成片。**

而不是：

> "所有画面都由 Seedance 生成。"

不为使用 AI 而强制所有镜头 AI 化（SKILL.md 默认禁止行为第 5 条）。

一支真实交付的企业/政府宣传片，制作方式通常是混合的：

```text
SHOT-01  AI 生成
SHOT-02  客户实拍
SHOT-03  AI 生成
SHOT-04  后期动画
SHOT-05  AI + 客户产品图
SHOT-06  客户历史视频
SHOT-07  AI 生成
SHOT-08  后期包装
```

---

# 2. 制作经济学原则

这项服务的商业优势本身就是"高效率 + 低成本"，因此 Skill 不应只追求"理论最佳画面"。

判断依据不是"能不能做"，而是"值不值得做"。

## 2.1 一个典型对比

### 方案 A

```text
一次生成较长片段
多角色 + 复杂运动 + 复杂场景 + 多种参考素材
可能需要多次生成
```

### 方案 B

```text
3 个 8～12 秒镜头
每个镜头保持单一核心动作
通过动作、视线、运动方向和声音设计连接
必要时在剪映完成精细衔接
```

最终观感接近，但方案 B 的制作成本可能低很多。**Skill 应在无法稳定使用 MULTI_SHOT 时选择 B，并避免把镜头默认压缩成 5 秒。**

## 2.2 内部判断字段

```text
镜头复杂度：较高
生成失败风险：中
预计迭代次数：2-4
AI 生成成本：低
后期剪辑成本：低
推荐方案：拆分为多个完整动作段落
衔接设计：明确前段结束状态、后段起始状态及动作/声音/视觉媒介连接点
```

## 2.3 内容倾向

优先交给 AI 的内容：

```text
概念视觉、空间场景、光影氛围、抽象隐喻
非真实的人物动作、B-roll、空镜
```

优先不交给 AI 的内容：

```text
精确中文长文字
复杂中文 UI
精确数据表格
真实人物口型讲话
需要像素级准确的产品文字
真实政府建筑 / 地标（除非有参考图）
```

# 3. 镜头级制作方式分类

每个镜头必须明确主要制作路径。以下分类仅用于说明 AI、参考素材与后期的组合方式，不作为工作模式选项，也不要求在交付中反复强调分类编号。

## 直接 AI 生成

适用：

```text
概念视觉
宏观场景（城市、园区、未来感空间）
单主体简单动作
氛围镜头
无事实风险的内容
```

## AI + 参考素材

适用：

```text
真实人物（客户提供照片）
真实产品（客户提供产品图）
真实建筑/场景（客户提供照片）
需要运镜参考的复杂镜头
需要风格参考的统一视觉
```

## AI 生成 + 后期修正

适用：

```text
画面主体由 AI 生成，精确信息由后期叠加
例如：AI 生成屏幕空间与光影 → 后期叠加准确中文数据
例如：AI 生成产品场景 → 后期叠加 Logo
```

## 不建议纯 AI

适用：

```text
精确中文长文字
复杂中文 UI
精确数据表格
品牌 Logo 主视觉
高精度政策文本
领导真实讲话（口型 + 声音高要求）
高度合规敏感内容
```

处理方式：实拍 / 客户素材 / 正版素材库 / 后期制作。
仍必须输出提示词：判断为不建议纯 AI 的镜头不跳过 Prompt Engineering。输出时：

1. 在提示词旁标注【建议优先采用实拍 / 客户素材 / 素材库 / 后期】。
2. 明确提醒用户：该镜头仍提供可直接用于 AI 生成的提示词；旁注用于说明风险、适用边界和更稳妥的替代方案。
3. 若用户仍决定用 AI 生成，按实际需求调整提示词，并记录 Override。

# 4. AI 适配度双评级

适配度评级分两级：**类型级**决定大方向，**镜头级**决定具体执行。

## 4.1 AI Native Score（类型级适配度）

不同视频类型的 AI 制作适配度天然不同
（类型判断与具体形态定义见 `video-types.md`）：

| 类型 | AI 适配 |
| --- | --- |
| 概念品牌片 | 很高 |
| 产品概念片 | 很高 |
| 科技产品视觉片 | 很高 |
| 城市 / 园区形象 | 较高 |
| 招商推介 | 较高 |
| 项目成果 | 中等 |
| 招聘 | 中等 |
| 培训 / 操作 | 中等 |
| 客户证言 | 较低 |
| 领导讲话 | 较低 |
| 活动回顾 | 较低 |

低分不代表不能用 AI，而是决定"AI 应该放在哪里"：

> 客户证言：真人采访负责"事实和信任"，AI 负责"场景化 B-roll"。

## 4.2 镜头级适配度评级

每个镜头给出适配度评级（与复杂度评级互补，不是一回事）：

```text
很高  非常适合 AI（如：城市夜景，灯光缓慢亮起）
较高  适合 AI，需少量参考素材
中等  可以 AI，但需后期配合
较低  风险较高（如：真实人物讲话且口型完全正确）
很低  不适合纯 AI（如：复杂软件界面需出现准确无误的中文数据）
```

评级依据：

```text
事实精度要求
人物真实度要求
文字/Logo 精度
动作复杂度
口型/对话要求
合规敏感度
一致性难度
```

# 5. 项目级制作策略

在 Creative Strategy 阶段形成项目级分工预估，Storyboard 阶段细化为镜头级决策。

项目级策略示例：

```text
【AI 策略】
以 AI 生成为主，结合客户实拍 / 历史素材，并将精确信息交由后期图表 / 数据包装。
具体比例根据项目内容和交付要求确定，不设固定指标。

【推荐重点】
城市 / 园区空间视觉
产业场景
企业生产场景
未来规划视觉

【不建议 AI】
领导讲话
具体政策文件
精确统计数字
```

项目级策略是指导性比例，不是硬性指标。
最终以镜头级判断为准。

# 6. 素材来源规划

Storyboard 阶段即为每个镜头规划素材来源：

| 镜头 | 内容 | 推荐来源 |
| --- | --- | --- |
| SHOT-01 | 城市鸟瞰 | AI |
| SHOT-02 | 企业真实厂房 | 客户图片 + AI |
| SHOT-03 | 产品外观 | 客户产品图 + AI |
| SHOT-04 | 产品 UI | 后期 |
| SHOT-05 | 员工操作 | AI |
| SHOT-06 | 真实客户案例 | 客户历史视频 |

这一步直接服务于"高效率、低成本"的商业目标，能极大减少后期返工。

## 6.1 素材缺口处理

```text
镜头需要客户素材但客户未提供
↓
列入 Brief / Storyboard 的待确认项
↓
明确告知：缺少该素材将降级为纯 AI 方案或需要实拍
↓
用户决定
```

不得假装素材存在并直接按“使用参考素材”的路径规划。

# 7. 镜头级制作策略字段

每个镜头最终形成简洁的制作策略块：

```text
【制作方式】
AI生成

【生成模式】
单镜头

【参考素材】
IMG-02
IMG-03

【后期】
添加中文数据文字

【风险】
产品 Logo 可能出现变形
```

该字段被 Seedance Prompt 阶段直接读取，是 Storyboard → Prompt 的关键接口。

---

# 8. 决策优先级

镜头制作方式判断时，按以下顺序考虑：

```text
1. 事实与合规要求（Fact Lock 内容能否交给 AI？）
2. 精度要求（文字 / Logo / 数据 / 口型）
3. 一致性难度（是否需要跨镜头稳定）
4. 客户素材可用性
5. AI 生成失败率与返工成本
6. 时间与预算
```

## 8.1 成本意识

每个制作方式决策都应隐含成本判断：

```text
AI 生成成本：低，但高复杂度镜头返工率高
客户素材成本：最低，但受素材质量限制
实拍成本：高，通常不在本服务范围内，仅作建议
后期成本：中，精确内容的最优解
```

当两种方案效果接近时，选择返工风险更低的方案。

---

# 9. 高复杂度镜头的拆分策略

镜头复杂度（评级维度见 SKILL.md 第 25 节 Storyboard Complexity Check）超过阈值时，按以下顺序处理：

```text
1. 拆镜：把一个长动作拆成多个完整动作段落，避免无理由压缩为过短片段
2. 调整制作路径：在 AI、参考素材和后期之间重新分工
3. 合并连续简单镜头：在风险可控时使用 MULTI_SHOT，减少独立片段拼接
4. 设计衔接：为每段补充 start_state、end_state、transition_out 和 edit_in_out
5. 简化：减少主体数量、减少动作数量
6. 转后期：把精确信息（文字 / 数据 / UI）交给后期
```

原则：

> **用连续镜头解决叙事，用剪辑解决不必要的复杂动作。**

# 10. 与 Seedance 阶段的接口

Production Strategy 输出供 Prompt 阶段消费：

```yaml
production_plan:
  - shot_id: SHOT-04-02
    primary_path: AI + 参考素材
    ai_suitability: 高
    generation_mode: IMAGE_TO_VIDEO
    references:
      - IMG-01
    post_production:
      - 后期叠加中文数据
    risks:
      - 产品 Logo 变形风险
    fallback: 若 AI 生成两次不达标，改用客户实拍素材
```

规则：

1. 每个镜头都必须生成对应的 Prompt，确保团队拿到所有画面的生成提示词。
2. 不建议纯 AI 的镜头，Prompt 仍须输出；同时在 Prompt 旁标注建议优先采用的替代方式、适用边界、风险与 fallback。若用户坚持使用 AI，按实际需求调整并记录 Override。
3. 需要后期配合的镜头，Prompt 只描述 AI 负责的画面主体、动作、空间和氛围，不为后期负责的精确文字、Logo、UI、数据等内容提出生成要求；同时在 Prompt 旁标注后期接管项。
4. 每个镜头都应给出 `fallback`（失败后备用方案）。

# 11. 特殊内容处理矩阵

| 内容类型 | AI | 参考素材 | 后期 | 说明 |
| --- | --- | --- | --- | --- |
| 人物（虚构） | ✔ | 可选 | — | 强锚点锁定 |
| 人物（真实） | 谨慎 | 必须 | — | 需授权参考图 |
| 真实建筑 | 谨慎 | 必须 | — | 客户照片优先 |
| 产品外观 | ✔ | 必须 | — | 产品图锁定 |
| 产品 UI | ✘ | — | ✔ | 后期制作 |
| 中文长文字 | ✘ | — | ✔ | 后期叠加 |
| 短标题/单词 | 可 | — | 可 | 视模型能力，保守起见仍建议后期 |
| Logo | ✘ | — | ✔ | 后期叠加 |
| 精确数据 | ✘ | — | ✔ | 图表后期 |
| 政策文本 | ✘ | — | ✔ | 必须原文，后期 |
| 宏观场景 | ✔ | — | — | AI 最擅长 |
| 概念视觉 | ✔ | 可选 | — | AI 最擅长 |
| 多人物对话 | 谨慎 | 可选 | 配音 | 优先拆镜或实拍 |
| 复杂机械操作 | 谨慎 | 视频参考 | — | 降低复杂度 |

# 12. Production Strategy Quality Gate

提交前检查：

```text
□ 每个镜头都有明确的主要制作路径
□ 不建议纯 AI 的镜头是否有替代执行方案
□ 使用参考素材的镜头是否已在资产库中登记
□ 需要后期配合的镜头是否明确后期分工
□ 每个镜头是否都有 fallback
□ 项目级 AI / 素材 / 后期比例是否合理
□ 是否存在"为了 AI 而 AI"的镜头
□ 素材缺口是否都已标记待确认
```

## 12.1 成本优化检查

每个镜头提交前同步检查：

```text
□ 是否能通过后期 / 素材替代昂贵的 AI 生成
□ 是否能用更短的生成单元替代高失败率的长镜头
□ 是否存在不必要的多主体 / 多动作
□ 参考素材是否足够，还是需要反复生成试错
□ 该镜头失败后，是否有更低成本的备选方案
```

---

# 最终原则

> **先保证可生产，再追求视觉炫技。**
>
> 制作策略不是技术展示，而是商业决策。
> 最优方案 = 效果 × 成本 × 时间的综合最优，
> 而不是 AI 使用率最高。
