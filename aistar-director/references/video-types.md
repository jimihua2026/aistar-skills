# `references/video-types.md`

# Video Type Classification & Routing Protocol

本文档定义 `aistar-director` 如何根据已经确认的 Structured Brief，判断项目的视频类型、主次类型、具体视频形态和表达形式，并将判断结果交给 `creative-strategy.md`。

本文件解决的问题是：

> **客户说“我要做一个宣传片”，Skill 如何判断这个视频真正要完成什么传播任务，以及应该采用什么创作母类型。**

本文件不负责最终脚本、分镜或 Seedance Prompt。

---

# 1. 视频类型判断的核心原则

## 1.1 按“传播任务”判断，而不是按客户名称判断

客户给出的名称不一定等于真正的视频类型。

例如：

> “园区宣传片”

可能实际上是：

```text
主类型：招商/投资/政务说服型
次类型：项目/成果证明型
```

而：

> “企业宣传片”

可能实际是：

```text
主类型：品牌认知型
```

也可能是：

```text
主类型：招商/投资/政务说服型
次类型：品牌认知型
```

因此：

> `requested_video_form` 是客户要求的视频形式，不是最终 `video_type`。

---

# 2. 类型判断的核心问题

判断一个视频属于什么类型，优先回答：

### Q1
视频为什么要制作？

对应：

> Business Objective

### Q2
视频最希望影响谁？

对应：

> Primary Audience

### Q3
希望观众看完后产生什么改变？

对应：

> Desired Perception Change

### Q4
希望观众采取什么行动？

对应：

> Desired Action

### Q5
视频最核心要证明、解释、传播或说服什么？

对应：

> Core Message

类型判断必须优先依据以上五项。

---

# 3. 八大创作母类型

`aistar-director` 使用以下八类作为一级分类：

```text id="7d4b93"
A｜品牌认知型
B｜产品/服务转化型
C｜项目/成果证明型
D｜招商/投资/政务说服型
E｜人物/信任型
F｜人才/组织型
G｜知识/培训/政务服务型
H｜活动/传播型
```

一个项目可以同时存在：

```text
Primary Type
+
Secondary Type
```

但必须确定唯一的：

> `Primary Type`

---

# 4. A｜品牌认知型

## 4.1 核心任务

回答：

> **“你是谁？为什么值得被记住和信任？”**

主要目标：

- 建立品牌认知
- 建立品牌形象
- 传递价值观
- 建立长期信任
- 塑造品牌气质
- 建立品牌差异化

---

## 4.2 常见场景

- 企业品牌宣传
- 企业形象片
- 品牌故事
- 企业文化片
- 城市形象片
- 园区形象片
- 周年片
- 企业使命愿景片
- 品牌升级片
- 品牌发布片

---

## 4.3 典型受众

- 潜在客户
- 合作伙伴
- 投资者
- 社会公众
- 员工
- 政府及产业合作方

---

## 4.4 核心叙事问题

不是：

> “我们有哪些东西？”

而是：

> “我们为什么值得被记住？”

---

## 4.5 常见叙事方向

```text id="w8jkv6"
时代 / 环境变化
→ 问题 / 机会
→ 品牌出现
→ 品牌能力
→ 品牌价值
→ 真实成果
→ 未来愿景
```

但不得将该结构视为唯一模板。

---

## 4.6 常见视觉特点

- 高质量品牌空间
- 真实人物
- 产品/业务场景
- 大尺度环境
- 品牌色彩
- 具有统一视觉母题
- 情绪驱动
- 相对克制的文字信息

---

## 4.7 AI 适配度

**★★★★☆**

特别适合：

- 概念视觉
- 大尺度场景
- 品牌 B-roll
- 抽象视觉化
- 未来愿景

不宜完全依赖 AI：

- 真实领导讲话
- 真实客户证言
- 真实企业活动
- 真实工厂生产过程

---

## 4.8 常见失败模式

- 变成公司简介 PPT
- 大量信息堆叠
- 每个镜头都像广告
- 只有“宏大”没有真实细节
- 所有镜头都强调科技感
- 没有核心品牌记忆点

---

```text id="x43n6v"
产品解决什么？

怎么解决？

为什么更好？

```

## 5.4 常见叙事结构

```text id="yr7lzo"

→ 问题
→ 产品出现
→ 工作方式
→ 核心优势
→ 应用场景
→ 结果
→ 差异化
→ CTA
```

---

## 5.5 常见视觉特点

- 产品特写
- 使用场景
- 产品动作
- 前后对比
- UI / 数据视觉化
- 功能示范
- 用户行为
- 结果展示

---

## 5.6 AI 适配度

**★★★★★**

特别适合：

- 产品概念展示
- 使用场景模拟
- 产品与人物互动
- 概念化机制展示
- 产品环境变化

需要后期处理：

- 精确 UI
- 精确参数
- Logo
- 长中文文字
- 精确数据

---

## 5.7 常见失败模式

- 只展示产品，不解释价值
- 功能太多
- 所有功能平铺
- AI 生成的产品外观发生变化
- 把精确 UI 交给模型生成
- CTA 不明确

# 6. C｜项目/成果证明型

## 6.1 核心任务

回答：

> **“你说有能力，那么证据是什么？”**

核心逻辑：

> **事实 → 过程 → 结果**

---

## 6.2 常见场景

- 项目成果片
- 工程纪录片
- 客户案例
- 项目汇报片
- 成果展示片
- 招投标展示片
- 项目建设片
- 客户案例片
- 项目总结片

---

## 6.3 核心受众

- 政府领导
- 企业客户
- 投资者
- 合作伙伴
- 项目相关方
- 招投标评审人员

---

## 6.4 常见叙事结构

```text id="gu9djx"
背景
→ 原有问题
→ 项目目标
→ 解决方案
→ 建设过程
→ 落地场景
→ 结果
→ 数据证明
→ 价值
```

---

## 6.5 常见视觉特点

- 真实场景
- 项目建设
- 数据
- 前后变化
- 使用场景
- 人物工作
- 客户反馈
- 工程过程

---

## 6.6 AI 适配度

**★★★☆☆**

AI 更适合：

- 补充 B-roll
- 概念解释
- 不方便实拍的视觉
- 过渡镜头
- 抽象数据视觉

事实性内容优先使用：

> 客户真实素材 + 后期包装。

---

## 6.7 常见失败模式

- 数据没有证据
- “成果片”拍成广告片
- 虚构真实项目过程
- 用 AI 代替真实工程证据
- 没有“项目为什么有价值”的解释

# 7. D｜招商/投资/政务说服型

## 7.1 核心任务

回答：

> **“为什么你应该投资、合作、进入这里或采取行动？”**

这是企业/政府项目中的重点类型。

---

## 7.2 常见场景

- 招商片
- 投资推介片
- 营商环境片
- 产业推介片
- 城市招商片
- 园区招商片
- 项目推介片
- 政务宣传
- 政策宣传
- 城市投资宣传

---

## 7.3 核心受众

通常是：

- 潜在投资企业
- 企业决策者
- 投资机构
- 政府招商部门
- 合作伙伴

---

## 7.4 核心叙事逻辑

不是：

> “我们这里很漂亮。”

而是：

> **“这里为什么值得你进入？”**

---

## 7.5 常见叙事结构

```text id="2e4a8p"
宏观机会
→ 区位
→ 产业
→ 资源
→ 基础设施
→ 政策
→ 成功案例
→ 发展前景
→ 行动
```

根据项目不同，可调整为：

```text
投资机会
→ 项目价值
→ 产业基础
→ 配套能力
→ 风险降低
→ 回报潜力
→ 行动
```

---

## 7.6 常见视觉特点

- 城市大景
- 园区空间
- 产业场景
- 企业生产
- 交通
- 基础设施
- 人才
- 生活环境
- 数据图表
- 地图
- 规划愿景

---

## 7.7 AI 适配度

**★★★★☆**

非常适合：

- 城市/园区宏观视觉
- 未来规划
- 产业场景
- 概念化经济活动
- 环境氛围

谨慎处理：

- 真实政府建筑
- 真实园区
- 领导形象
- 真实统计数据
- 具体政策

---

## 7.8 常见失败模式

- 变成旅游宣传片
- 只有城市美景，没有投资逻辑
- 信息非常宏大但没有证据
- 虚构政策
- 虚构企业
- AI 生成真实建筑错误
- 产业信息堆叠却没有主线

# 13. 主类型判断

项目必须选择一个：

> `PRIMARY_TYPE`

判断优先级：

```text id="14fms2"
Business Objective
>
Desired Action
>
Audience
>
Core Message
>
Requested Video Form
```

例如：

### 案例 1

客户：

> “我们想做一个园区宣传片，用于招商会。”

进一步发现：

> 主要目标是吸引企业投资。

判断：

```text id="bfzj34"
PRIMARY:
D 招商/投资/政务说服型

SECONDARY:
A 品牌认知型
```

---

### 案例 2

客户：

> “做一个企业宣传片，主要给客户介绍我们在 AI 领域的技术实力。”

如果重点是：

> 技术能力 + 企业可信度

可判断：

```text id="2okpny"
PRIMARY:
A 品牌认知型

SECONDARY:
C 项目/成果证明型
```

---

### 案例 3

客户：

> “拍我们最新产品，让客户看懂怎么用。”

判断：

```text id="s6ubta"
PRIMARY:
B 产品/服务转化型
```

---

# 14. Secondary Type

第二类型用于描述：

> **主要传播任务之外，对创作具有实质影响的辅助任务。**

例如：

```text id="1r7h8r"
PRIMARY:
B 产品/服务转化型

SECONDARY:
A 品牌认知型
```

不是所有项目都需要 Secondary Type。

如果没有明显辅助目标：

> 可以为空。

最多建议：

> 一个 Primary + 一个 Secondary。

如果出现第三种以上强目标：

> 提示信息过载风险，并回到 Brief 检查传播目标优先级。

---

# 15. Hybrid Type

某些项目天然属于混合型。

例如：

> 城市招商片 + 城市形象展示 + 项目成果。

不要强制选一个类型。

采用：

```text id="6grmyj"
Primary:
D 招商/投资/政务说服型

Secondary:
A 品牌认知型

Supporting Mode:
C 项目/成果证明型
```

但对后续 Strategy 仍然必须确定一个主要叙事任务。

---

# 16. Requested Form 与 Type 的转换

客户常见名称与母类型之间不建立固定一一映射。

例如：

| 客户说法 | 可能类型 |
|---|---|
| 企业宣传片 | A / C / D |
| 园区宣传片 | A / C / D |
| 产品宣传片 | B / A / C |
| 项目宣传片 | C / A / D |
| 城市宣传片 | A / D / H |
| 招商宣传片 | D / A / C |
| 品牌视频 | A |
| 企业文化片 | A / F |
| 招聘视频 | F / E |
| 案例视频 | C / E |
| 政策宣传片 | G / D / H |

因此：

> 不能根据客户给出的名称直接确定类型。

---

# 17. Expressive Form

母类型确定后，再确定：

> **表达形式**

建议支持：

```text id="f2g5vw"
广告片
纪录片
故事片
访谈片
人物纪录
科技视觉片
概念片
产品 Demo
动画解释
数据可视化
新闻/资讯
活动纪实
短视频
混合形式
```

Expression Form 回答：

> **“这个内容应该以什么方式讲出来？”**

它不能取代 Primary Type。

例如：

```text id="8l4ghu"
Primary:
招商/投资说服型

Expression Form:
科技纪录片
```

---

# 18. Expression Form 选择规则

表达形式主要由：

```text id="r1xkly"
Audience
Brand Tone
Desired Emotion
Reference Works
Available Assets
Budget
AI Capability
```

共同决定。

不要仅仅因为 Personal Style 喜欢某种形式就强制使用。

---

# 19. Type Confidence

Skill 对类型判断需要给出：

```text id="t9x5gq"
HIGH
MEDIUM
LOW
```

### HIGH

Objective、Audience、Core Message 高度一致。

### MEDIUM

大体明确，但存在两个合理解释。

### LOW

关键信息缺失，多个类型都成立。

LOW 时：

> 应优先进入 Brief 补充，而不是强行生成 Strategy。

---

# 20. Type Conflict

如果出现：

```text id="9bpw5v"
Requested Form:
传统企业宣传片

Objective:
招商转化

Audience:
投资企业

Desired Action:
预约考察
```

Skill 可以提出：

> 判断为招商说服型，而不是单纯品牌认知型。

但必须明确：

```text id="v6hjjj"
客户原始形式：
传统企业宣传片

AI判断：
招商/投资/政务说服型

AI建议：
……
```

不得直接修改客户要求。

---

# 21. Type Overload

如果 Brief 出现：

```text id="z8kf3k"
品牌认知
+
产品销售
+
招商
+
招聘
+
政策传播
+
培训
```

不应直接形成一个“万能视频”。

应该提示：

> 传播目标过载。

建议：

```text id="mm3xx4"
选择 Primary Objective
+
最多 1 个 Secondary Objective
```

必要时建议拆成多个视频。

# 24. Type Routing 原则

`video-types.md` 负责：

> **判断“属于哪一类”**

`creative-strategy.md` 负责：

> **判断“这一类具体应该怎么做”**

因此不要在本文件中写完整：

- Script
- Storyboard
- Prompt

只提供：

> 类型知识、判断依据、推荐骨架和路由信息。

---

# 25. 重新分类触发条件

已经确定 Type 后，如果发生以下变化：

- Business Objective 改变
- Primary Audience 改变
- Desired Action 改变
- Core Message 改变

必须重新进行 Type Classification。

如果只是：

- 色彩变化
- 配音变化
- 一个镜头变化
- BGM变化

一般不需要重新分类。

---

# 26. Personal Style 对 Type 的影响

Personal Skill 可以影响：

- Expression Form 推荐
- Visual Style 推荐
- 具体参考风格

但不得改变明显由 Brief 决定的 Primary Type。

例如：

> 创作者喜欢纪录片。

项目仍然可能是：

> 产品/服务转化型。

可以选择：

> 纪录片式产品视频。

但不能因为个人喜欢纪录片，就把项目重新定义成人物/信任型。

---

# 27. Type 与 AI 生产的关系

视频类型只决定：

> **AI 应该承担什么角色。**

不决定：

> **全部内容必须 AI 生成。**

例如：

```text id="55n7f0"
人物/信任型：
真人采访 = 核心
AI B-roll = 辅助

招商型：
AI 城市/产业视觉 = 核心辅助
真实政策/数据 = 后期

项目成果型：
真实项目素材 = 核心
AI 概念视觉 = 辅助
```

---

# 28. Final Classification Principle

始终遵循：

> **先看传播目标，再看受众和行动；先判断项目真正要完成的任务，再决定它叫什么视频。**

视频类型不是一个标签。

它是后续：

> **叙事策略、视觉策略、制作策略和 AI 使用方式的路由入口。**

因此，正确的类型判断是整个 `aistar-director` 后续创作质量的重要基础。
