# `references/visual-assets.md`

# Visual Asset Planning Protocol

本文档定义 `aistar-director` 如何在 Script 确认之后、详细 Storyboard 拆分之前，
建立整个项目的**视觉资产库（Visual Asset Library）**，并通过资产 ID 与锚点机制
保证跨镜头的视觉连续性。

本文件回答的问题：

> **这部片子里"谁、什么地方、什么东西"必须始终保持一致？如何让每一个镜头引用同一套视觉世界，而不是重新发明它？**

---

# 1. 为什么需要视觉资产库

AI 视频生成最常见的失败不是"画面不美"，而是：

```text
第一个镜头的人，第二个镜头像另外一个人；
第一个镜头的办公室，第二个镜头变成另一个地方；
手里的设备、服装、道具不断变化。
```

根因是：

> 每个镜头都在重新描述视觉世界。

视觉资产库的核心原则：

> **分镜引用资产，而不是每个镜头重新描述资产。**

先锁定人物、场景、产品的视觉锚点，再进入动作与镜头设计。

---

# 2. 建立时机

```text
Script → LOCKED
↓
Visual Asset Planning   ← 本文件
↓
Storyboard
↓
Seedance Prompt
```

Visual Asset Planning 在 Script 锁定后启动，与 Storyboard 阶段同步完善。

不得跳过资产规划直接拆分镜，否则后续所有镜头失去统一参照。

## 2.1 资产库建立流程

```text
1. 扫描 Script，找出反复出现的稳定主体
2. 分类：人物 / 场景 / 产品 / 道具
3. 逐个分配 ID（CHR / SC / PRD / OBJ / IMG / VID / AUD）
4. 为每个重要资产建立档案并定义视觉锚点
5. 区分强锚点与弱锚点
6. Storyboard 与 Prompt 阶段统一引用这些 ID
```

示例：

```text
人物
CHR-01  女工程师（30 岁左右）
CHR-02  企业负责人（50 岁左右）

场景
SC-01  智慧城市控制中心
SC-02  工业园区

产品
PRD-01 智慧城市管理平台
PRD-02 智能终端设备

道具
OBJ-01 平板电脑
OBJ-02 工程师工作证
```

# 3. 资产分类与 ID 体系

## 3.1 标准资产类别

| 前缀 | 类别 | 说明 | 示例 |
| --- | --- | --- | --- |
| `CHR` | 人物 | 片中出现的稳定角色 | CHR-01 女工程师 |
| `SC` | 场景 | 反复出现的空间环境 | SC-01 智慧城市控制中心 |
| `PRD` | 产品 | 客户产品、平台、设备 | PRD-01 智慧城市平台 |
| `OBJ` | 道具 | 跨镜头出现的关键物件 | OBJ-01 平板电脑 |
| `IMG` | 参考图片 | 客户或制作方提供的图片素材 | IMG-01 产品官图 |
| `VID` | 参考视频 | 用于动作/运镜/风格参考的视频 | VID-01 客户历史 footage |
| `AUD` | 参考音频 | 音乐、节奏、声音参考 | AUD-01 品牌音乐 |

## 3.2 编号规则

```text
类别前缀-两位序号
```

示例：

```text
CHR-01  女工程师
CHR-02  企业负责人
SC-01   智慧城市控制中心
SC-02   工业园区
PRD-01  智慧城市平台
OBJ-01  工程师工作证
IMG-01  企业建筑实拍照片
VID-01  参考运镜视频
AUD-01  品牌BGM
```

规则：

1. ID 在项目内唯一，建立后不得复用、不得改指。
2. 资产废弃时标记 `deprecated`，不得删除编号。
3. ID 与 Script / Storyboard / Prompt 中的引用保持一致（见 `terminology.md`）。

# 4. 资产档案结构

每个资产必须建立档案：

```yaml
asset:
  asset_id: CHR-01
  name: 女工程师
  category: character
  source: ai_generated | client_provided | stock | mixed
  anchor_strength: strong | weak

  description: |
    30岁左右女性，黑色短发，浅灰色西装，
    白色内搭，银色细框眼镜。

  strong_anchors:
    - 面部特征
    - 发型
    - 服装颜色与款式

  weak_anchors:
    - 表情
    - 细微姿态

  reference_files:
    - IMG-01

  fact_lock: false        # 是否属于客户事实资产
  usage_scope: 全片       # 或指定 SEC/SHOT
  notes:
```

# 5. 强锚点与弱锚点

不要把所有资产的所有细节都锁死。

> "同一个办公室"不意味着每个镜头桌子、灯、背景物必须完全相同。

真正需要锁定的是：

> **能决定观众判断"这是同一个人 / 同一个场景 / 同一个产品"的关键特征。**

## 5.1 强锚点（Strong Anchors）

不能轻易变化：

```text
人物面部特征
人物发型
人物服装
产品外形
产品颜色
主要建筑外观
品牌主色
```

## 5.2 弱锚点（Weak Anchors）

允许自然变化：

```text
桌面小物件
远景人员
背景细节
次要陈设
非关键光影变化
```

## 5.3 一致性执行优先级

跨镜头保持一致时，按以下优先级执行：

```text
已确认的客户素材 / 锁定资产档案
>
项目视觉锚点
>
上一镜结束状态与下一镜开始状态
>
当前镜头新增创意
```

每个镜头只改变当前叙事所必需的内容。环境、人物和物品没有被明确要求改变时，默认沿用上一镜状态，不重新设计。

## 5.4 一致性控制清单

进入 Storyboard 和 Prompt 前，必须为反复出现的资产建立以下字段：

```yaml
continuity_card:
  asset_id: CHR-01 | SC-01 | PRD-01 | OBJ-01
  must_preserve:          # 必须保持
  must_not_change:        # 不得改变
  acceptable_variation:   # 可自然变化
  reference_priority:     # 该资产的首选参考文件
  last_confirmed_shot:     # 最近一次确认外观的镜头
```

最低要求：

- 环境：空间结构、时间段、主光方向、主色调、关键固定物位置。
- 人物：面部特征、发型、服装、年龄感、身份特征、主要动作习惯。
- 物品：轮廓、尺寸比例、材质、颜色、关键接口或结构、与人物的相对位置。

## 5.5 锚点冲突处理

如果某个镜头需要突破强锚点（例如换装、夜景模式）：

1. 标记为 `anchor_break`。
2. 说明理由与叙事必要性。
3. 在 REVIEW 阶段向用户明确提示。
4. 用户确认后才允许进入 Prompt。

# 6. 资产来源与客户素材

## 6.1 来源类型

```text
client_provided   客户提供（照片 / 视频 / Logo / VI手册 / 历史素材）
ai_generated      AI 生成后选定的资产参考图
stock             正版素材库
mixed             组合方式
```

## 6.2 客户素材优先原则

涉及以下内容，优先要求客户提供参考素材：

```text
真实人物
真实建筑
真实产品
品牌视觉
真实项目场景
```

原因：

- 降低事实风险（Fact Lock）。
- 提升一致性稳定性。
- 符合企业/政府项目的真实性要求。

如果客户无法提供，标记为：

```text
AI 建议：使用 AI 生成参考图，需客户确认后锁定为资产
```

## 6.3 素材不足时的处理

```text
客户素材缺失
↓
判断是否影响强锚点
↓
影响 → 列入待确认，向客户索取
不影响 → AI 生成参考方案，用户确认后纳入资产库
```

# 7. 视觉锚点的三个层次

资产规划必须同时维护三类锚点：

## 7.1 叙事锚点

观众理解故事所依赖的稳定元素：

```text
主角是谁
核心场景是什么
关键产品是什么
```

## 7.2 视觉锚点

观众识别"同一个世界"所依赖的视觉特征：

```text
人物外观
场景关键结构
产品外观
色彩体系
光线逻辑
```

## 7.3 情绪锚点

全片统一的氛围基调：

```text
克制 / 激昂
冷峻 / 温暖
科技 / 人文
```

三类锚点继承自 Creative Strategy 与 Script，不得在 Storyboard 阶段擅自改变。

# 8. 资产引用规则

## 8.1 引用而非重述

Storyboard 与 Prompt 中引用资产 ID：

```text
CHR-01 在 SC-02 中操作 PRD-01
```

而不是：

```text
一位30岁左右黑色短发穿浅灰色西装的女性工程师，
在一个宽敞的现代工业园区中，操作一个银灰色的智能终端……
```

## 8.2 镜头只描述增量

每个镜头只改变：

```text
景别
动作
镜头运动
当前叙事重点
```

其余维持资产锚点稳定。

## 8.3 参考素材职责分离

当一个资产附带多个参考文件时，必须明确每个文件的职责：

```text
IMG-01 → 人物身份外观
IMG-02 → 场景构图
VID-01 → 运镜方式
```

禁止让一个参考文件同时控制多个属性（详见 `seedance.md` 参考资产职责规则）。

允许一个参考文件承担一个主职责，并产生不超过两个次要影响；但次要影响不得与其他参考文件冲突，也不得覆盖锁定的资产档案。

## 8.4 跨镜头引用纪律

- 首次出现的环境、人物或物品，使用经过确认的主参考素材建立基准。
- 后续镜头优先引用同一资产 ID 和同一主参考素材，不随意更换参考图。
- 发生视角、景别或姿态变化时，只改变镜头需求，不重写资产身份特征。
- 若生成结果出现漂移，先回到资产参考和上一镜状态，不要只通过堆叠负面词补救。

# 9. 资产库与全流程的接口

## 9.1 输入

```text
Creative Strategy → 视觉方向、风格基调
Script → required_assets、叙事锚点
客户素材 → 事实资产
```

## 9.2 输出

```yaml
visual_asset_library:
  characters:
    - asset_id: CHR-01
      ...
  scenes:
    - asset_id: SC-01
      ...
  products:
    - asset_id: PRD-01
      ...
  objects:
    - asset_id: OBJ-01
      ...
  reference_files:
    - asset_id: IMG-01
      role: 人物外观
    - asset_id: VID-01
      role: 运镜参考
  style_anchors:
    lighting:
    color:
    texture:
  continuity_rules:
    - 全片保持冷白环境光 + 品牌蓝点缀
```

## 9.3 下游消费

```text
Storyboard → 每个 SHOT 引用资产 ID
Production Strategy → 判断资产来源与制作方式
Seedance Prompt → @资产引用 + 连续性约束
```

# 10. 资产变更管理

资产库建立后，如需变更：

```text
资产变更请求
↓
影响分析：哪些 SHOT / PROMPT 引用了该资产
↓
列出受影响范围
↓
用户确认
↓
更新资产档案（升版本）
↓
同步更新受影响下游对象
```

不得在 Prompt 阶段临时修改资产定义。

若发现资产定义有问题：

1. 指出问题。
2. 说明影响范围。
3. 提议回退到 VISUAL_ASSETS 阶段或创建 Change Request。
4. 等待用户决定。

（完整变更机制见 `workflow.md`。）

---

# 11. Visual Asset Quality Gate

资产库提交用户确认前，自动检查：

```text
□ 是否覆盖 Script 中所有 required_assets
□ 每个资产是否有明确 ID 与档案
□ 强锚点 / 弱锚点是否已区分
□ 涉及事实的资产是否已有客户素材或标记待确认
□ 参考文件是否标明职责
□ 是否存在两个资产描述同一对象（重复资产）
□ 是否存在 Script 从未使用的冗余资产
□ 风格锚点是否与 Creative Strategy 一致
```

全部通过后才能进入 Storyboard。

# 12. 常见错误

## 12.1 资产过度描述

错误：

> 为每个资产写 300 字外观散文。

正确：

> 只记录影响识别一致性的关键特征。

## 12.2 锚点全锁

错误：

> 场景中每个物件都列为强锚点。

正确：

> 只锁决定"同一性判断"的特征，其余留给自然变化。

## 12.3 资产与素材混淆

错误：

> 把客户提供的一段历史视频同时当成"场景定义"和"动作参考"和"风格参考"。

正确：

> 一个参考文件一个主职责，写入资产档案的 `role` 字段。

## 12.4 跳过资产直接分镜

错误：

> Script 确认后直接写 Storyboard，镜头里各自描述人物。

正确：

> 先建库，再拆镜，全程引用。

---

# 最终原则

> 视觉资产库不是美术设定集，而是全片的"一致性契约"。
>
> 它存在的唯一目的，是让第 1 个镜头和第 30 个镜头里的
> 人、场景、产品，被观众认作同一个世界。
