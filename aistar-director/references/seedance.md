# `references/seedance.md`

# Seedance 2.0 Prompt Engineering Protocol

本文档定义 `aistar-director` 如何将已锁定的 Storyboard、Visual Asset Library
和 Production Strategy 转化为可直接用于 Seedance 2.0 / 即梦的生成提示词。

流程位置：

```text
Requirement
↓
Video Type
↓
Creative Strategy
↓
Script
↓
Visual Assets
↓
Storyboard
↓
Production Strategy
↓
Seedance Prompt   ← 本文件
```

本文件回答的问题：

> **如何把导演语言（Storyboard）翻译成模型语言（Prompt），让 Seedance 稳定地执行这个镜头？**

---

# 1. Prompt 的定位

最终 Prompt 必须同时满足三个条件：

## 1.1 对创作人员

看到 Prompt 就知道：

> 这个 Prompt 打算让 Seedance 生成什么。

## 1.2 对模型

能够明确理解：

> 谁 / 什么 → 做什么 → 在哪里 → 怎么拍 → 什么风格 → 什么声音 → 哪些必须保持稳定。

## 1.3 对制作流程

能够追溯：

> 这个 Prompt 来自哪个脚本段落、哪个分镜、哪些视觉资产。

因此每个 Prompt 都有唯一 ID，保持双向追踪：

```text
SEC-04
↓
SHOT-04-02
↓
PROMPT-04-02-V1
```

---

# 2. 两阶段生成（硬规则）

不要从分镜一次跳到最终 Prompt。

## 第一步：Prompt Plan（内部结构）

```text
prompt_plan:
  prompt_id: PROMPT-04-02-V1
  source_shot: SHOT-04-02
  mode: SINGLE_SHOT
  subject: CHR-01
  action: 查看屏幕
  scene: SC-02
  camera: 慢推
  style: 继承视觉锚点
  audio: 系统提示音
  references:
    - IMG-01 → 人物身份
    - IMG-02 → 场景构图
  post_production: 中文UI后期叠加
  complexity: L1
  risk: 低
```

Prompt Plan 是内部结构，默认不展示给用户。

## 第二步：Prompt Render（最终输出）

将 Prompt Plan 渲染为：

> **可直接复制到即梦的自然语言导演指令。**

两阶段分离的价值：

> 未来 Seedance 升级或更换模型时，只需修改 Render 层，Plan 层与上游方法论保持不变。

---

# 3. Prompt Mode

根据镜头特征自动判断生成模式：

| Mode | 名称 | 适用场景 |
| --- | --- | --- |
| `SINGLE_SHOT` | 单镜头生成 | 一个镜头、一个主动作、需要高稳定性 |
| `MULTI_SHOT` | 多镜头连续生成 | 多个叙事连续的简单镜头组成一段连续叙事，具体时长以当前平台能力和项目需求为准 |
| `IMAGE_TO_VIDEO` | 图生视频 | 已有确定首帧/人物/产品/场景参考图 |
| `MULTIMODAL_REFERENCE` | 多模态参考生成 | 需要同时参考图片+视频+音频的复杂镜头 |
| `VIDEO_EXTEND` | 视频延长 | 已生成片段需要延续动作或时长 |
| `VIDEO_EDIT` | 视频编辑/修改 | 在已有生成结果上做局部调整 |

最常见的是 `SINGLE_SHOT` / `IMAGE_TO_VIDEO` / `MULTIMODAL_REFERENCE`。

## 3.1 Mode 选择原则

```text
简单镜头
→ 一个镜头一个 Prompt（SINGLE_SHOT）

中等复杂、叙事连续的简单镜头组
→ 优先一个多镜头 Prompt（MULTI_SHOT），具体时长以当前平台能力和项目需求为准

复杂宣传片
→ 多个完整动作段落 + 视频延长或后期剪辑
```

核心原则（硬规则）：

> **在不显著增加生成风险的前提下，尽量用足当前平台支持的时长。**
>
> 多个连续画面优先在同一个 Prompt 内完成，减少独立片段硬拼造成的突兀。
>
> 但不要为了凑满平台时长，把多个复杂镜头塞进一个 Prompt；高风险内容仍应拆分为独立生成，每段也要设计完整的起始状态、动作过程和结束落点。

# 4. Prompt 核心结构：9 个模块

内部生成逻辑按以下顺序组织：

```text
1. 主体       谁/什么是画面主体
2. 动作       主体发生了什么变化
3. 场景       在什么空间，主体与空间什么关系
4. 摄影       景别、机位、运镜——摄影机怎么观察
5. 时间结构   起始状态、动作触发/展开/完成、结束状态与剪辑落点
6. 风格       光线、色彩、质感（继承视觉锚点）
7. 声音       BGM / 环境声 / 音效 / 人声
8. 参考资产   每个参考素材负责什么
9. 连续性/约束 必须保持什么稳定
```

注意：

> 这是内部逻辑顺序，最终交付的 Prompt 是压缩后的自然语言，
> 不要求机械显示这些标题。

## 4.1 主体

明确"谁/什么是画面主体"。

不要：

> 一个工程师

而是：

> CHR-01 所代表的 30 岁左右女性工程师

重要原则：

> **参考素材负责"长什么样"，Prompt 负责"做什么"。**

已有参考图片时，文字不重复堆砌外观描述。

## 4.2 动作

Prompt 最重要的部分之一。必须明确：

> **发生了什么变化？**

可执行：

> 工程师抬头看向屏幕。

不可执行：

> 工程师充满自信、从容而专业地工作。

默认规则（硬规则）：

> **一镜一个主动作。**

"走进房间、坐下、打开电脑、查看数据、拿起手机、打电话"——
应自动判断拆成多个镜头。

## 4.3 场景与空间关系

告诉模型：

> 在什么空间里？主体和空间是什么关系？

推荐：

> 宽敞的现代城市指挥中心，工程师位于前景中央，大型弧形城市数据屏幕位于背景。

不推荐：

> 高科技智慧城市指挥中心。

后者只有概念，没有空间结构，模型无法理解构图。

## 4.4 摄影（运镜）

运镜必须说明：

> **摄影机怎么变化，以及为什么变化。**

不推荐：

> 电影级运镜

推荐：

> 摄影机从人物侧后方缓慢向前推进。

更好：

> 工程师发现异常后，摄影机缓慢向屏幕推进，将注意力从人物转移到异常区域。

最后一种已经与叙事发生关系——让镜头观察重要的动作。

## 4.5 风格

继承视觉资产库中的风格锚点：

```text
整体风格：写实企业宣传片
光线：冷白环境光，局部蓝色屏幕光
色彩：中性灰 + 品牌蓝
质感：真实商业摄影
```

硬规则：

> Prompt 不得每个镜头自己重新创造风格。
> S01 写实、S02 科幻、S03 赛博朋克——全片将失去统一视觉语言。

## 4.6 声音

Seedance 2.0 支持原生音画联合生成，应充分利用，但区分层次：

```text
环境声：城市低沉环境噪声
动作音效：键盘轻触声、系统提示音
人物声音：女性工程师低声说……
音乐：极简、渐进式电子氛围音乐
```

声音不能喧宾夺主。按项目类型自动判断主次：

| 项目类型 | 声音优先级 |
| --- | --- |
| 品牌片 | BGM 为主 |
| 产品演示 | UI / 操作音效优先 |
| 人物纪录 | 人声 / 环境音优先 |
| 政策解读 | 旁白优先 |

## 4.7 参考资产

Seedance 2.0 支持图片、视频、音频与文字的混合参考，可分别用于提供构图、角色、动作、运镜和声音依据。具体支持的素材数量、时长和功能，以当前即梦/Seedance 页面及账号权限为准；本 Skill 不把平台动态限制写成固定硬规则。

硬规则：**每个参考素材必须有唯一主职责。**

```text
IMG-01 → 人物身份
IMG-02 → 产品外形
IMG-03 → 场景构图
VID-01 → 运镜
VID-02 → 动作节奏
AUD-01 → 声音节奏
```

禁止：

> "参考以上所有素材。"

禁止让一张图片同时决定：人物 + 场景 + 摄影角度 + 服装。
多素材控制同一属性会产生意图冲突。

一般原则：

> 图片负责外观/构图，视频负责动作/运镜，音频负责声音/节奏。

## 4.8 连续性 / 约束

最后一个模块不是大量"禁止词"，而是：

> **必须保持什么稳定。**

例如：

```text
保持人物身份、发型、服装颜色和产品外形与参考素材一致。
保持场景布局和主要光线逻辑一致。
动作自然，人物手部结构稳定。
不新增第二件产品。
```

规则：

> **正向描述优先 + 必要约束少量使用。**

不要生成一长串"不要模糊、不要畸变、不要多手指……"——
过多负面约束可能适得其反，直接描述希望得到的结果更有效。

# 5. 最终 Prompt 的逻辑顺序

内部生成顺序：

```text
1. 当前镜头是什么
2. 主体是谁
3. 主体做什么
4. 在什么环境
5. 摄影机怎么看
6. 光线和视觉风格
7. 声音
8. 参考素材分别做什么
9. 必须保持什么
```

最终压缩为自然、简洁、可执行的一段导演指令。

## 5.1 完整示例

分镜输入：

```text
SHOT-04-02
画面：夜晚城市道路出现局部拥堵，交通数据逐渐聚合到城市管理平台。
主体：城市道路 + 数据变化
运镜：高空俯视缓慢推进
风格：真实城市宣传片
声音：城市环境声 + 轻微电子提示音
参考：IMG-01（城市空间与视觉风格）
```

最终 Prompt：

> 夜晚的现代城市道路，高空俯视视角，多条道路车流平稳运行，其中一个大型十字路口逐渐出现拥堵，摄影机从城市上空缓慢向该区域推进，异常区域的数据节点依次亮起并形成清晰的数据流，最终汇聚到智慧城市管理平台的视觉中心。真实商业宣传片质感，冷静克制的蓝灰色城市夜景，真实光影和自然车辆运动。保持城市道路结构稳定，不新增无关建筑。环境中有真实城市交通声，异常发生时加入轻微电子提示音。参考 @IMG-01 的城市空间和视觉风格。

这就是目标形态：

> **导演语言，而不是关键词堆。**

# 6. Prompt 复杂度控制

内部为每个 Prompt 计算 Complexity Score，考察维度：

```text
主体数量
动作数量
场景复杂度
镜头运动复杂度
参考素材数量
声音复杂度
一致性要求
文字/Logo要求
```

## 分级

### L1｜简单单镜头

> 1 主体 + 1 动作 + 1 运镜

直接生成，单镜头 Prompt。

### L2｜标准生产镜头

> 1～2 主体 + 1～2 动作 + 复杂场景

单镜头 Prompt + 必要参考素材。

### L3｜多镜头 Prompt

> 多个简单镜头组成连续 sequence

MULTI_SHOT 模式优先使用平台当前支持的较完整时长；仅在复杂度、连续性或一致性风险升高时缩短。

### L4｜高风险

> 多人物互动 + 连续动作 + 对话 + 复杂场景

自动建议：

> **拆镜，或改用实拍/素材/后期。**

---

# 7. Prompt 风险标记

生成 Prompt 前自动检查下表：

| 风险项 | 默认处理 |
| --- | --- |
| 人脸 | 使用参考图 |
| 产品外观 | 使用产品图 |
| Logo | 后期叠加 |
| 中文长文字 | 后期叠加 |
| 精确 UI | 后期制作 |
| 多人物互动 | 尽量拆镜 |
| 多人对话 | 谨慎，优先实拍或后期配音 |
| 复杂手部动作 | 降低动作复杂度 |
| 真实政府建筑 | 使用参考图 |
| 真实领导形象 | 合法授权参考素材 |
| 连续场景 | 视觉资产锚点 |
| 复杂运镜 | 视频参考优先 |

命中风险项时，必须在交付中标注风险提示与建议处理方式。

---

# 8. 后期接管原则（硬规则）

不要让 Prompt 承担后期软件该做的工作。
但“交给后期”不等于“不输出提示词”：不建议纯 AI 的镜头仍必须输出提示词，标注【参考 / 兜底】，并提醒用户建议采用实拍 / 素材 / 后期方案。

默认优先交给后期（剪映等）：

```text
精确中文长文字
复杂中文 UI
精确数据表格
品牌 Logo
需要像素级准确的产品文字
高精度政策文本
```

AI 主要承担：

```text
人物
场景
动作
空间
光影
氛围
概念视觉
```

典型分工示例：

```text
产品参考图 → AI 负责产品整体外观与动作
Logo → 后期叠加

AI 生成屏幕空间和光影 → 后期叠加准确中文数据
```

# 9. Prompt 修改规则

用户对 Prompt 提出修改时：

1. 定位修改对象（哪个模块：Subject / Action / Camera / Style……）。
2. 只修改必要部分。
3. 分析影响范围。
4. 保留未修改部分。
5. 创建新版本（V1 → V2）。

示例：

```text
用户："运镜太慢。"

修改：
Camera Block
慢速推进 → 中速推进

影响：当前 Prompt
不影响：Script / Storyboard / Visual Assets
```

原则：

> 生成结果接近目标时逐项修改，不要每次重写整个 Prompt。

---

# 10. Prompt Quality Gate

提交用户确认前，自动执行 10 项检查：

```text
□ 主体是否明确
□ 主动作是否明确
□ 是否只有一个主要 Beat
□ 运镜是否具体
□ 场景空间是否明确
□ 风格是否继承视觉锚点
□ 参考资产是否各司其职
□ 连续性要求是否明确
□ 是否把不适合 AI 的工作交给后期
□ 是否存在不必要的复杂度
```

全部通过后才进入 `PROMPT · REVIEW`。

---

# 11. 最终交付结构

每个 Prompt 交付时包含三部分：

## ① 可直接复制的 Prompt

主产物，自然语言导演指令。

## ② 使用方式

```text
模式：图生视频
参考素材：IMG-01、IMG-02
建议时长：优先使用平台当前支持的较完整时长；只有高风险镜头才适当缩短
生成后进入剪映添加中文 UI
```

## ③ 风险提示

```text
产品 Logo 不建议由模型直接生成，使用后期叠加。
```

让团队执行人员不需要重新理解这个 Prompt。

---

# 12. 禁止事项（硬规则）

Seedance Prompt 阶段不得：

1. 把 Brief 原文直接塞进 Prompt。
2. 把脚本旁白整段重复进 Prompt。
3. 把每个分镜写成文学散文。
4. 堆砌"电影感、震撼、8K、顶级、史诗"等空泛形容词。
5. 一个镜头塞入大量连续动作。
6. 让多个参考素材同时控制同一视觉属性。
7. 要求 AI 准确生成长中文文字、复杂 UI 或精确 Logo。
8. 为了追求一次生成较长片段，强行把多个复杂镜头塞在一起。

---

# 13. 与模型的解耦

Seedance 2.0 是当前主要执行引擎，但本 Skill 的方法论不硬编码为 Seedance 专用。

```text
Brief / Strategy / Script / Storyboard / Visual Assets / Production Strategy
→ 保持模型无关

Model-specific Prompt Renderer
→ 可替换
```

未来更换视频模型时，只需重写 Render 规则，上游全部保留。

---

# 最终原则

> 脚本决定为什么拍，分镜决定拍什么，Prompt 决定怎么生成。
>
> 好的 Prompt 不是词汇最华丽的，而是模型失败率最低、
> 创作人员拿到就能用、生成结果可追溯的。
